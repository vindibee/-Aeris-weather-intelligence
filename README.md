# Aeris — Weather Intelligence Platform

Полноценное веб-приложение о погоде: анимированный лендинг с 3D-глобусом,
авторизация и личный кабинет с интерактивными метео-картами.

## Быстрый старт

Двойной клик по **`start.cmd`** — поднимутся оба сервера и откроется браузер.

Или вручную:

```bash
npm install          # один раз
npm run dev          # API :4000 + фронт :5173
```

| Что | Адрес |
|---|---|
| Фронтенд | http://localhost:5173 |
| API | http://localhost:4000/api/health |

### Тестовый аккаунт

```
email:  demo@aeris.app
пароль: demo1234
```

Аккаунт создаётся автоматически при первом запуске сервера и уже содержит
6 сохранённых городов. На странице входа есть кнопка «Войти в демо-аккаунт».

## Структура

```

  src/lib/       БД (node:sqlite), JWT-авторизация, кэш, транслитерация,

                 stations.js — опорная сеть для поиска экстремумов
  src/routes/    auth · weather · locations · space
  src/data/      space_weather.json — справочник планет для fallback
  data/          aeris.db (создаётся автоматически)

                     WeatherMap · weather/* · space/* · wardrobe/*
  src/pages/         Landing · Auth · SpaceWeather · dashboard/*
  src/lib/           capitals + cities (178 меток) · outfit (гардероб)
                     indices (бытовые индексы)
  src/lib/           api-клиент · погодные утилиты · zustand-store
  src/hooks/         React Query + трансформация прогноза
```

## Источники данных (все бесплатные, без API-ключей)

| Провайдер | Что даёт |
|---|---|
| [Open-Meteo Forecast](https://open-meteo.com) | прогноз на 16 суток, 20+ параметров, модели ICON/GFS/ECMWF |
| [Open-Meteo Air Quality](https://open-meteo.com/en/docs/air-quality-api) | European AQI, PM2.5, PM10, NO₂, SO₂, O₃ (CAMS) |
| [Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api) | поиск городов (кириллица транслитерируется на сервере) |
| [RainViewer](https://www.rainviewer.com/api.html) | радарная мозаика осадков, кадры за 2 часа |
| [BigDataCloud](https://www.bigdatacloud.com/) | обратный геокодинг для клика по карте |
| [OpenFreeMap](https://openfreemap.org) + OpenMapTiles | векторная базовая карта без ключа и лимитов (dark / positron), подписи на русском |
| [NASA Open API](https://api.nasa.gov) | InSight Mars Weather, DONKI (вспышки и геомагнитные бури) — для раздела «Погода в космосе» |

## API

```
GET  /api/health
POST /api/auth/register        { name, email, password }
POST /api/auth/login           { email, password }
POST /api/auth/logout
GET  /api/auth/me
PATCH /api/auth/me             { name?, units?, theme?, avatarHue?, home? }
GET  /api/auth/activity

GET  /api/weather/forecast     ?lat&lon&units&days
GET  /api/weather/geocode      ?q
GET  /api/weather/reverse      ?lat&lon
GET  /api/weather/bulk         ?points=lat,lon;lat,lon&units
GET  /api/weather/grid         ?north&south&east&west&cols&rows
GET  /api/weather/radar

GET  /api/weather/extremes     ?kind=hot|cold|wind — мировой экстремум сейчас

GET  /api/space/weather        сводка по 8 планетам + солнечная активность
GET  /api/space/planet/:id     одна планета

GET    /api/locations
POST   /api/locations          { name, lat, lon, ... }
DELETE /api/locations/:id
PUT    /api/locations/order    { ids: [] }
```

Ответы провайдеров кэшируются в памяти (TTL 4–20 мин) с single-flight —
одинаковые параллельные запросы уходят наверх один раз.

### Если по точке нет данных

Провайдер может промолчать: дыра в сетке модели, полярная шапка, отсутствие
населённого пункта для обратного геокодинга. Вместо прочерков сервер расширяет
радиус поиска кольцами (0 → 25 → 60 → 150 → 350 → 800 км, по 8 азимутов на
кольцо) и берёт ближайшую точку с наблюдениями. Кольцо опрашивается целиком и
параллельно, так что на него уходит один сетевой раунд, а не восемь.

Ответ несёт поле `fallback` с исходными и фактическими координатами и
расстоянием — интерфейс честно пишет «в этой точке наблюдений нет, показана
ближайшая, в N км отсюда», а не выдаёт чужие данные за данные этой точки.
Логика вынесена в `server/src/lib/nearest.js` и покрыта юнит-тестами.

## Возможности

**Лендинг** — 3D-глобус на Three.js (кастомные шейдеры: фре­нелевая атмосфера,
точечная оболочка, дуги данных, орбитальный спутник). Вращается только руками:
drag-to-rotate по всем осям с инерцией, никакого автоповорота и параллакса «сам
по себе»; зум включается после первого касания, чтобы колесо сначала листало
страницу. Метки — **178 городов**: столицы (янтарные) и крупнейшие агломерации
(бирюзовые). Наведение показывает подпись, клик открывает сводку погоды с
«Одеватором». Бегущая строка, scroll-анимации, aurora-фон.

**Одеватор** — подбор одежды по ощущаемой температуре, ветру, UV и осадкам:
верхняя одежда, средний слой, низ, головной убор, обувь, аксессуары (зонт при
осадках, очки при UV ≥ 3). Рядом — 3D-фигура, собранная процедурно из
примитивов: цвет и состав одежды меняются вместе с набором. Пол берётся из
профиля; если он не указан или пользователь не вошёл — показываются обе модели.

**Бытовые индексы** в кабинете
- **Автомойка** — риск осадков на трое суток; ближний день весит больше
- **Сушка белья** — время высыхания через дефицит давления пара и ветер
- **Выгул питомцев** — температура асфальта (ожог лап от 52 °C), мороз, реагенты

**Охотник за экстремумами** — кнопки «самое жаркое / холодное / ветреное».
Сервер опрашивает опорную сеть из ~110 станций (места, регулярно ставящие
рекорды, плюс равномерная сетка), глобус плавно доворачивается к найденной
точке, рядом открывается карточка с метриками и справкой о локации.

**Кабинет**
- Текущая погода: анимированный фон под текущие условия (дождь/снег/облака/молнии на canvas), 6 быстрых метрик, восход/закат
- Почасовой график на 24/48/72 ч с переключением метрик (температура, осадки, ветер, влажность, давление, UV)
- Прогноз на 14 дней с диапазонными полосами температур и раскрытием деталей
- Компас ветра, солнечная дуга, качество воздуха, индекс комфорта, тренд давления, плитки метрик
- **Карта**: русскоязычные подписи, слои температуры / осадков / облачности / влажности (интерполированный битмап поверх MapLibre), анимация ветровых частиц на canvas, радар RainViewer с таймлайном и авто-проигрыванием, клик по точке → мини-прогноз
- Сохранённые локации с живыми карточками, поиск с автодополнением, геолокация
- Настройки: метрические/имперские единицы, тёмная/светлая тема, домашняя точка, журнал активности

**Погода в космосе** (`/space-weather`)
- Восемь планет, у каждой — свой процедурный 3D-глобус, который вращается мышью
  (полосы газовых гигантов, кольца Сатурна и Урана, фрактальный рельеф каменистых)
- Три режима просмотра: климатические пояса (экватор тёплый, полюса ледяные,
  линии тропиков и полярных кругов), медленное автовращение, полный экран
  с повышенной детализацией шума и сетки
- Модальная карточка с метриками: температура и её разброс, атмосферное давление,
  скорость ветра, состав атмосферы, гравитация, сутки, год, спутники
- Панель солнечной активности: класс и время вспышек, геомагнитные бури, индекс Kp
- Каждая карточка честно помечена: **live** — данные пришли из внешнего API,
  **резерв** — из локального `server/src/data/space_weather.json`
- У Земли — кнопка бесшовного перехода на главный 3D-глобус с картой столиц

**Безопасность**: bcrypt-хеши, JWT в httpOnly-cookie (+ Bearer-фолбэк для
не-браузерных клиентов), zod-валидация всех входов, helmet, CORS-allowlist,
общий лимит на API и отдельный жёсткий лимит на вход — 15 попыток за 10 минут,
причём успешные входы его не расходуют. Токен в браузере хранится только в
памяти вкладки: сессию через перезагрузку держит кука, которую JS не читает.
Подробнее о защитном режиме — в разделе «Прод-сборка».

## Интернационализация

Интерфейс переведён на шесть языков: украинский, русский, английский, немецкий,
французский, испанский. Переключатель — в шапке лендинга и кабинета, выбор
хранится в localStorage и переживает перезагрузку.

Словари лежат в `web/src/i18n/locales.ts`. Русский — эталон: тип `Dictionary`
выводится из него, поэтому забыть ключ в другом языке компилятор не даст.

## Вход через Google и Telegram

| Способ | Что нужно настроить |
|---|---|
| Пароль | ничего, работает из коробки |
| Google OAuth2 | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` |
| Telegram Login | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` + домен, привязанный в @BotFather |

Кнопки появляются только для настроенных провайдеров — `GET /api/auth/providers`
сообщает фронту, что доступно.

Провайдеры связаны с одной моделью `User`: поиск идёт по внешнему id, затем по
подтверждённой почте. Человек, зашедший сначала паролем, а потом через Google,
получает ту же учётку, а не вторую.

Подпись Telegram Login Widget проверяется по алгоритму из документации
(HMAC-SHA256 от отсортированной строки полей, секрет — SHA-256 от токена бота),
сравнение постоянное по времени, данные старше суток отклоняются.

## Telegram-бот

Отдельное приложение на Python + aiogram в каталоге `bot/`. Подробности —
в [bot/README.md](bot/README.md).

```bash
pip install -r bot/requirements.txt
cp bot/.env.example bot/.env    # вписать свой TELEGRAM_BOT_TOKEN
python -m bot.main
```

Онбординг с выбором языка, бесплатные функции (одноразовая ссылка входа на
сайт, погода по городу или геолокации), премиум через Telegram Stars или
Crypto Pay с планировщиком рассылки три раза в день (APScheduler).

Погоду бот не считает сам — ходит в то же API, что и сайт, поэтому прогноз и
подбор одежды всегда совпадают.

### Защитный режим

`NODE_ENV=production` включает набор ограничений, которые в разработке только
мешают, а в интернете обязательны. Часть из них — жёсткие: сервер не стартует,
пока переменные не заданы. Это сделано намеренно — молчаливый фолбэк на
дефолтное значение опаснее падения, потому что выглядит как рабочая система.

| Что меняется | Поведение в production |
|---|---|
| `JWT_SECRET` | обязателен, минимум 32 символа; дев-заглушка отвергается — иначе токены подписаны строкой из публичного репозитория |
| `CORS_ORIGINS` | обязателен; послабление для локальной сети (`192.168.*`, `10.*`, `172.16-31.*`) выключено, работает только явный список |
| Кука сессии | `secure: true` — уходит только по HTTPS |
| Демо-аккаунт | не создаётся; нужен осознанно — `SEED_DEMO=1` |
| `BOT_API_SECRET` | обязателен, минимум 32 символа, если задан `TELEGRAM_BOT_TOKEN` |

Генерация секрета:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

### Маршрут выдачи кодов входа

`POST /api/auth/telegram/issue` выдаёт одноразовый код входа в **любой** аккаунт
по Telegram id — фактически мастер-ключ, поэтому защита у него двойная: общий
секрет с ботом плюс приём только с локального хоста. Проверяется адрес сокета,
а не `X-Forwarded-For`: заголовок клиент подделывает, адрес сокета нет.

Если бот вынесен на отдельную машину, ограничение снимается через
`BOT_ISSUE_ALLOW_REMOTE=1` — но тогда доступ к маршруту нужно закрывать
файрволом или доверенной сетью.

### Чеклист выката

- [ ] сайт за HTTPS, `WEB_ORIGIN` указывает на боевой домен
- [ ] домен привязан в @BotFather (`/setdomain`) — без этого Telegram Login

- [ ] секреты, которые были в дев-окружении, перевыпущены: токен бота через
